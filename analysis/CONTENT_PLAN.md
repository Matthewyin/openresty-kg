# 范围与基础知识继续实施方案

日期：2026-10-10。承接网站 W01–W04 通过后用户明确授权，当前优先网站知识质量，Codex 宿主接入继续后移。

## 目标与边界

先逐组件核定 OpenResty 1.27.1.1 随包范围，明确哪些组件提供 Nginx 配置指令，哪些仅提供 Lua API、运行时或工具。43 个下载项不是 43 个指令模块；未取得固定版本证据的组件不标完成。基础内容需真实功能、配置入口与补丁影响证据，机械注册数不能冒充功能完成。

本批先补 worker_processes、worker_connections、multi_accept、accept_mutex、accept_mutex_delay 的基础说明，以固定源码及实际有效补丁审计核对事实。不把这 5 项当全量完成门槛，也不据自选内容宣称部门深度样例完成。

## 角色及写入范围

- 主线程：流控、缺失组件固定版本读取、盘点接入、构建实测与最终验收。
- 规划 Astra low：只更新 CONTENT_PLAN.md 与独立范围研究说明；给出组件分类判据、分批顺序和可检查范围。
- 实施 Sol high：仅更新 knowledge/directives.json 中上述 5 项，写 analysis/CONTENT_WORKER_FACTS.md 研究证据；不得改构建、查询或盘点数据。
- 审核 Astra low：只写 analysis/CONTENT_REVIEW.md；逐条核对计划、固定源码、补丁结论及实际发布。

若角色限流，主线程接手受阻工作并记录实际执行者，不假称完成并行角色，不未经确认换模型。

## 验收条件

1. 每项范围结论有组件版本、完整 revision、路径或固定源码树证据，不由仓库名或缺少简单文本命中推出“无指令”。新增注册项保留 registration_only。
2. 上述基础知识的语法、功能、默认/继承、限制、配置入口及补丁核实范围准确；仅核实的事实计入 basic_verified，不编译或运行 OpenResty。
3. 构建和契约测试通过，浏览器/共享查询从实际发布读到新内容；计数与来源一致，历史发布仍可用，8 个参考项不进入指令计数。
4. 独立审核发现问题必须修改并复核；全量知识、范围总分母、部门样例、部署、手机视口与 Codex 真实接入分别保留状态。

不新增后端、数据库、在线生成或语义分析；不修改源仓库用户改动、不运行 mirror-tarballs，不改变已锁定 tag。

## 本批冻结的范围判据与推进顺序

完整对照需求、实施计划、当前 components.json、inventory.mjs、build.mjs，并只读核对 OpenResty 固定版本源码。详细分类、来源链接和风险见 [CONTENT_SCOPE_NOTES.md](CONTENT_SCOPE_NOTES.md)。以下细化优先用于本批范围验收，不把程序功能通过、18/876 或 8 个参考项扩展为内容全量完成。

1. 主线程逐项对照锁定 `util/mirror-tarballs` 的 43 个有效下载语句、版本及重命名，建立下载项到源码组件、构建选择和最终知识类型的映射。43 是发行版取得源码的清单，不能作为指令模块分母；Nginx 一个下载项下还包含多种核心/HTTP/stream/mail/event 模块。
2. 编译选择单独记录：默认选择、显式可选、依赖/平台条件、仅安装库/工具、未核实。以固定 `util/configure`、Nginx `auto/options`/`auto/modules`、各模块 config/Makefile/生成器为依据。源码随包与默认选择均不能证明实际部署启用；本批不编译，也不读取生产环境。默认禁用但随包的指令仍属需求范围，标条件，不删出分母。
3. 分类优先核对尚缺源码的模块候选，先查 NDK 和依赖它的模块、lua-upstream 的注册/注入路径，再查其他第三方模块；库、运行时与工具随后核定知识类型。仅查到完整固定树及构建入口才能缩小读取集合；无 C 命中保持待核实，不能宣布无配置指令。
4. 主线程按既定 agent-reach/gh API 路径解析 tag 到完整 commit SHA，读取该 SHA 的完整 tree 和必要源码，不读取 master，不运行全 bundle。树响应截断/权限失败/限流时保留缺口，由主线程接手，不更换已确认模型、不将失败计作零指令。非 GitHub 下载项须单独建立发行版归属和可追溯固定来源，不能伪造 GitHub revision。
5. 扫描使用固定 SHA 的文件清单与内容，覆盖 `.c`、`.h`、模块 config、生成器和被引用模板/包含文件。记录模块结构持有的 commands 指针，追踪宏展开、NDK 指令宏及生成注册路径；条件分支保留，不根据当前机器裁掉注册项。未知表达式或归属不明进入缺口，而不是过滤后静默成功。只读生成器，不执行 configure/make 或生成脚本。
6. 新发现项只作为 registration_only 进入后续主线程接入；源码版本、模块、context、callback、条件和固定来源齐全后才可进入目录。远程范围笔记不能直接假装满足当前 build 的本地 Git 读取条件：主线程单列“范围已核定、目录已接入、构建可用、基础已核实”四个状态。接入方式由主线程按既有授权处理，本规划不修改脚本或产品。
7. 实施线程并行完成已有计划指定的五项核心知识，审核按固定注册、配置入口、默认/继承和有效补丁范围核对。它们在范围盘点未完时也可独立交付，不等全部组件齐备；其中已有基础项只是补齐/复核，不重复新增身份或计数。不以这五项代替全量基础知识。

每组件至少记录：下载项/版本/来源行、完整 revision 或尚缺原因、树是否完整、构建角色及条件、读取文件/排除理由、注册或非配置结论及证据、宏/生成/补丁待办、目录/构建/功能状态。只有所有43项都有可复核终态，且生成路径、模块归属、补丁新增/删除注册均无未说明缺口，才可宣布发行版指令范围核定；当前 inventory 的 `scope_complete` 不能单独证明该结论。

## C-R05 最小返工方案（本轮补充，优先于旧回放口径）

当前仅 C-R05 阻断本批：默认 patch 输出未报告全部成功 hunk 的 offset/fuzz，原“34项均成功、无offset/fuzz”结论撤回，旧记录保留为被撤回的历史依据，不作为通过证据。集合选择仍固定为已核定的34项及原应用顺序、OpenResty/Nginx完整revision、替换规则；不为通过门禁删补丁、改来源或调整顺序。返工只闭合回放证据、匹配门禁及受影响的五项事实，不重开已关闭问题。

最小契约采用主线程已报告完成并真实回放的实现：固定Git revision读取绑定34项实际补丁内容及顺序，audit固定替换规则；`--verbose` 配合C locale解析所有成功hunk；audit只持久化107项非零匹配及全部47个touched/oldtarget文件的最终SHA-256。本方案不要求补丁输入hash ledger、每阶段前后hash或跨平台patch工具识别，也不以这些未实现项拒绝交付。以下主线程实现状态来自其报告，独立审核仍须核对实际产物。

### 分工与执行顺序

1. 主线程负责门禁与audit：在隔离、固定版本源码副本上按34项顺序真实执行 `patch --verbose --batch --forward -p1`，使用C locale并保留实际输出。dry-run不替代连续实际应用，不操作用户源仓库；已有真回放满足此执行方式时直接用于审核，不要求另造回放系统。
2. 逐成功hunk解析 `{file,hunk,line,fuzz,offset}`，补丁身份及顺序由当前固定调用绑定。每个补丁的成功记录数必须等于实际补丁输入中的 `@@` hunk数，file/hunk归属及序号可核对；无法解析、缺hunk、重复、异常退出/失败/反向/跳过均拒绝。解析后明确输出零值作为观察记录，不由默认输出缺少关键词推断零匹配；不另将全部零值持久化为audit ledger。
3. audit只保存本次107项非零匹配，以补丁/file/hunk定位并精确比较line/fuzz/offset；缺期望项的默认条件为fuzz=0且offset=0，而不是任意匹配。新增未记录非零项、已记录项缺失或变成零、任一已记录值变化均失败；107项必须全部消费，无多余未消费记录。全部47个touched/oldtarget最终SHA精确比较，不能仅检查旧stream目标。观察输出与冻结期望分开，门禁不得自动将观察写回期望。
4. 非零offset/fuzz只允许固定revision、固定34项顺序及audit替换规则下已独立核定的精确映射，不设范围容差或通用放行开关。对每个fuzz匹配，独立审核以实际应用差异及固定补丁中被忽略的上下文核对真实落点；原文可由固定来源读取，不新增阶段hash账本。已核定offset不自动批准fuzz，未核定的非零值仍阻断。最终文件SHA绑定实际应用结果，但不替代对模糊上下文和相关事实的人工核对。
5. Sol high 修订五项研究notes及必要知识语义：撤回旧无offset/fuzz表述，在实际连续应用后的目标文件上逐项复核 worker_processes、worker_connections、multi_accept、accept_mutex、accept_mutex_delay 的配置入口、默认/继承、初始化、资源和事件处理事实。明确哪些所列事实不受影响、哪些受有效补丁影响；引用仍区分上游和补丁各自固定行号，补丁后文件对应audit哈希和来源映射，不能伪造上游GitHub行号。
6. 主线程汇总实际回放、audit、门禁正负例及发布验证；Astra low独立核对冻结34项、非零映射、47个最终目标哈希、模糊上下文和五项语义。Sol/Astra重点逐项核定五项相关最终事实，不扩展为全文知识重审。发现真实不一致须给具体hunk/文件/事实及证据，再退回责任方；不能以本最小契约之外未做ledger等事项拒绝交付。本规划不修改实现、audit或事实证据。
