已读取根目录 REQUIREMENTS.md、IMPLEMENTATION_PLAN.md、README.md，以及 [Pi 接入计划](PI_AGENT_SPEED_PLAN.md)和 [Pi 接入验收](PI_AGENT_SPEED_VERIFICATION.md)。旧需求仍声明 Q1–Q15 不变，旧计划仍以纯静态与 Codex 双入口为当前交付标准，README 已说明可选 Pi 服务；旧 CLAUDE 还以源码研究和禁止任何本地服务为总约束。这些冲突通过更新当前文档、保留原文历史解决，不改运行实现。

验收记录证明的是当时本机链路、回归和桌面操作通过，不证明部门服务器已部署，也不证明当前进程状态。精确结果缓存不等于共享语义检索。当前仅有两个自定义 tools，不具备 MCP/skills 管理；依赖包或 SDK 支持某能力不等于本项目已启用该能力。

## 4. ARCHITECTURE 与入口文件

ARCHITECTURE 按以下结构形成唯一架构说明，其他文档引用并保持一致：

1. **现状**：原静态站、版本化知识与源码、项目内 Pi 服务及 SDK、原 stdio MCP 接口的职责；本机验收证据与适用范围。
2. **目标部署（待设计）**：部门服务器是未来部署方向；server 与 Pi SDK 随项目管理。地址、访问方式、进程管理和持久化安排尚未形成已批准方案，不补写已部署结论，不引入多用户设计。
3. **数据流**：基础查询的浏览器解析与静态读取；明确 Agent 提交后的服务端解析/匹配、精简模型输入、字段选择、校验、知识原文恢复与展示；原 MCP 单项查询单列。原配置到服务端与模型收到精简数据必须区分。
4. **会话与缓存**：记录已有追问、恢复、取消、项目内会话持久化与精确缓存；主线程只读核对代码中的实际位置、缓存键与失效条件，不凭验收摘要补猜。说明跨会话精确命中仍不等于语义相似检索或共享成果治理。
5. **SDK 与 tools 限制**：只读核实两个自定义 tools 的准确名称、职责和可用路径；区别注册工具与优化路径实际零工具往返。不得把 SDK 自带能力、已安装依赖或原 stdio MCP 工具写成 Pi 已具备通用 MCP/skills 管理。
6. **未来边界**：共享检索与成果复用、通用工具、MCP/skills 的接入和管理分别列待设计，说明尚无实现验收及本轮实施授权，不预设向量数据库或具体选型。

README 提供需求、架构、实施状态、项目规则和历史原文入口，保留准确的现有使用说明；部署与 Codex 状态和上述口径一致。AGENTS 仅维护项目补充规则和事实来源入口，不复制全局规则；CLAUDE 仅兼容指向项目 AGENTS，不保留第二份规则正文。旧 CLAUDE 必须先备份再替换。

主线程可在 `experiments/pi-sdk/README.md` 仅补指向根目录 `ARCHITECTURE.md` 的现行架构链接（相对路径 `../../ARCHITECTURE.md`），明确实验文档定位，不改写实验说明或扩展范围。
