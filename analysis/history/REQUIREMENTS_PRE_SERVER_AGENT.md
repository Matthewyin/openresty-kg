# OpenResty 配置知识站 — 需求基线

> 更新：2026-10-15 · 状态：Q1–Q15不变；1041项基础内容、样例44项限定运行时及6项配置边界已验收；三个可靠性缺陷和状态同步已验收，现场验证、Codex宿主及内网部署未验收

执行顺序补充：依据用户最新指令，当前优先完成网站功能，Codex 真实接入在网站完成后实施。最终双入口目标不变；网站程序功能、知识全量、部门深度内容与实际部署分别验收。

## 一、正式目标与用途

建设部门内部使用的 OpenResty 配置知识站，并提供 Agent 查询入口。用户在网站或 Agent 中输入配置，能够识别配置项、理解其功能和已核实的限制，并追溯到锁定版本的对应实现代码。

两个入口共用同一套版本化知识。正式交付物包括供现有内网 Web 服务托管的静态站点及知识 JSON，以及供 Codex 使用的本地 MCP 接入工具和说明。中文源码研究报告、指令目录和机制说明是知识生产材料，不以报告数量替代查询效果验收。

两个入口均辅助理解配置和源码，不自动判断变更是否正确或安全，不替代实际环境中的配置检查。

## 三、用户查询流程

### 3.1 网站入口

1. 用户打开内网站点，浏览器加载页面、知识索引和所需知识文件。
2. 用户粘贴配置；浏览器解析指令、参数、位置和块层级，匹配对应模块与 context。
3. 点击识别出的指令，查看功能、相关配置信息及配置解析入口源码；已有深度内容时继续查看运行时调用链和机制说明。
4. 对缺失上下文、候选不唯一、未识别指令、解析错误及未提供的外部文件分别提示，不补猜为确定结论。

同名指令不能只按名称匹配，应结合 context 和模块区分。片段不足以确定 context 时，列出候选或提示信息不足，不直接判定配置无效。

同时支持按模块、context、相关阶段和指令名称浏览、搜索。阶段导航只展示实际相关阶段，不能假设每条指令均对应某个请求阶段。

### 3.2 Codex 入口

1. 用户在 Codex 中输入指令名称或单条配置，请求查询说明和限制。
2. Codex 调用本地 MCP 查询工具；工具确定性解析输入，不把指令识别交给模型猜测。
3. 工具根据静态索引、指令名及已提供的 context、模块等信息匹配候选，通过 HTTP 读取网站发布的对应知识 JSON，不向网站发送原始配置或参数值。
4. 工具返回结构化知识、Markdown 和详情链接；Codex 在对话中展示功能、已核实的限制及源码引用，用户可继续打开网站查看详情。

Agent 返回也遵守缺失上下文和同名指令的处理规则，不自动补猜模块或 context。未识别、候选不唯一、输入解析失败、超出单项范围和知识文件不可用分别明确提示，不能呈现为成功查询或以模型常识替代查证。

工具返回已有语法和参数说明，不据此宣称用户给出的参数值可在实际环境中生效。版本仍锁定 v1.27.1.1，不新增多版本查询要求。

## 四、知识内容与证据

### 4.1 全范围基础内容

支持范围内每条指令至少包含：

- 指令名称、所属模块、适用 context、语法和功能说明。
- 配置解析入口的源码符号、站内源码片段及组件、版本、路径、行号。
- 已核实的默认值或继承行为；尚未核实的补充信息明确标注，不作确定性描述。
- 条件编译、依赖及废弃状态；无此限制时不添加无关说明。
- 文档与源码依据，以及内容核实状态。

不得以只有名称和源码映射的一行记录替代功能说明。功能或配置解析入口未核实的指令计入覆盖缺口，不能计为基础内容已完成。

### 4.2 常用指令深度内容

在基础内容上补充配置回调到运行时处理函数的调用链、共享机制、限制、关联项和证据。优先级依据部门脱敏配置中的使用情况与变更关注点确定，不使用固定条数替代。

机制说明可由多条指令共用。Lua API 和变量作为参考项关联，不扩展为首版自动语义分析。

### 4.3 来源与版本

- 源码引用注明组件版本、可追溯的 revision、路径和行号，用户在站内即可查看片段。
- 区分上游 Nginx 1.27.1 源码与 OpenResty 补丁后的行为。受补丁影响的内容注明补丁及生效条件，不能直接把上游代码当作发行版最终行为。
- 主仓库补丁位于 `patches/`，例如 `patches/nginx-1.27.1-*.patch`；是否生效按 `util/mirror-tarballs` 的实际分支核定，不能仅按文件存在判断。
- 优先阅读测试规格并对照实现；只读测试不等于实测通过。重要机制结论用测试断言、官方文档等第二信号交叉核对，未能确认的内容标为“未验证”。

知识数据以指令、模块、机制说明和源码引用为核心，按需关联 Lua API、变量和文档。完整图谱不是首版上线前提。

## 五、实现与交付边界

### 5.1 共用知识与静态读取接口

知识生产和站点构建在开发阶段完成，产出 HTML、CSS、JavaScript、版本化知识 JSON、索引和源码片段等静态文件。网站页面与 MCP 工具均读取这些产物，不分别维护两份功能、限制或源码说明。

“网站 API”在首版指约定好的静态 JSON 读取接口：索引用于匹配候选，详情按知识标识读取。它不是接收配置并现场分析的动态接口，不接收配置分析 POST 请求，不提供现场生成或语义问答。具体路径与字段在最小链路验证时确定，不先增加通用搜索后端。

静态读取契约需能区分数据格式版本、知识发布版本与组件源码版本。索引、详情和源码引用必须对应一致的知识发布版本，不能静默混用；引用仍保留组件 revision、文件和行号。

查询结果包含匹配状态、指令与模块、适用 context、功能、语法、已核实的默认值或继承及限制、源码引用、核实状态和详情链接；已有深度内容时一并关联。未知或未核实信息保留明确状态，不填充为确定结论。

### 5.2 本地识别与展示

网站配置文本在浏览器内处理；Agent 的单项输入在本地 MCP 工具中解析。两者均不向知识站发送原始配置或参数值，不把它们放入请求地址、请求正文或日志上传。该要求约束知识站与接入工具的请求，不将用户已在 Agent 中输入内容表述为未被 Agent 宿主接收。

网站与 MCP 工具共用已验证的指令匹配规则，解析能力尽量复用，但入口范围不同：网站支持片段和完整文本，MCP 只支持单项。解析器需先验证再选型，处理注释、引号、分号、块层级和内嵌 Lua 边界；不能仅用正则查找名称，不为复用 Python 版 crossplane 引入 Python 后端。

MCP 工具基于共用知识生成 JSON 与 Markdown，提供用户可打开的网站详情及源码链接。展示需保留版本、限制、源码依据和核实状态，不能只返回缺少出处的摘要。Codex 的内容组织不改变知识事实，内嵌 HTML 留待宿主能力验证后再考虑。

本地 MCP 工具由 Codex 启动和管理，通过 stdio 通信，不开放本地 HTTP 端口，不独立作为守护服务部署。每位使用者需要安装并配置工具，且 Codex 执行环境需能访问内网站点；这是首版接入条件，不表示当前任务授权安装或修改 Codex 配置。

### 5.3 不纳入首版的能力与操作

知识更新通过重新构建并发布静态文件完成。首版不新增集中式业务后端、数据库、向量数据库或 RAG 问答，不提供在线编辑；已有知识的 Agent 查询与展示属于首版，不属于站点实时 AI 问答。

本项目不运行全 bundle 下载脚本，不编译 OpenResty，不启动常驻本地 HTTP 服务或 Understand dashboard；Codex 管理的 stdio MCP 接入进程按 Q15 执行。允许按需获取锁定版本源码、运行离线检查和构建交付产物。内网托管是交付目标，不表示当前任务授权操作托管环境，也不要求双击 HTML 文件即可完整使用。
