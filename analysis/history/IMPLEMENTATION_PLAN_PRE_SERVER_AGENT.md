## 一、推进原则

按用户最新决定，优先完成网站程序功能，再扩展全范围基础知识和部门常用深度内容；Codex 宿主真实接入在网站完成后实施。网站支持单条、片段和完整配置；Codex 首版通过本地 MCP 工具查询指令名称或单条配置。当前网站功能方案见 `analysis/WEBSITE_PLAN.md`。

两个入口共用版本化知识、指令匹配规则和源码引用。网站提供页面及静态 JSON 读取接口，本地 MCP 解析单项输入并读取知识，返回 JSON、Markdown 和详情链接；不新增集中式业务后端、数据库或向量数据库，不让网站或 MCP 现场调用模型生成解释。

源码报告是研究材料，不是主验收对象。代表样例不能替代全量基础覆盖，深度内容不能由任意固定数量决定。解析方案未经验证前，不冻结 crossplane 或其他具体选型；JSON 读取契约在 M2 验证，不预设复杂通用接口。

用户已授权启动实施并先完成通用链路。已按配置获取最小所需源码并实现网站和本地 MCP；未修改用户 Codex 配置，未操作内网托管环境。

## 四、M2：双入口链路验证

### 4.1 共用解析与网站入口

解析候选先检查浏览器可运行性和维护成本，再以边界样例验证。优先采用满足语法要求的最小方案；若现成解析器不适用，评估必要的词法与块结构解析，不为复用 Python crossplane 增加后端。

解析结果保留指令名称、参数、输入位置和块层级。匹配结合 context 和模块；片段的未知外层 context 保持未知，同名候选不强行合并。

最低验证样例：

- 单条指令、缺少外层 context 的片段，以及包含 http、stream 等嵌套块的完整配置。
- 注释、带空格的引号参数，以及引号内的 #、;、{、}；这些字符不能误终止配置项或块。
- 同名、未知和已废弃指令，分别核对候选、提示与知识匹配。
- 缺失分号、未闭合引号或块，显示错误位置，不把部分解析呈现为完整成功。
- 内嵌 Lua 的字符串、注释、长字符串和嵌套结构，只确定块边界，不分析 Lua 语义。
- include、外部 Lua 文件及带变量的参数，保留文本，不自动读取文件或求值，不声称外部内容已分析。

最小页面连接输入、可点击指令、功能说明和站内源码片段。加载与展示基于静态知识文件，原始配置和参数值不进入知识站网络请求。

检查分两层：先运行离线解析样例并与预期对照，再在浏览器检查实际页面、源码展示和网络请求。离线检查不能证明浏览器流程或无上传已经成立。

浏览器实测优先使用已有可访问的静态托管地址，或无需常驻服务的临时预览方式，不启动常驻本地服务。预览条件不足时记录该验收项未完成，不以构建成功替代实测。

### 4.2 静态 JSON 读取契约

用代表性知识构建静态索引与详情，约定候选匹配、按标识读取及链接方式，区分数据格式版本、知识发布版本与组件源码版本。索引、详情和源码须来自一致的知识发布版本，不静默混用内容。

结果应支持名称与模块、context、功能、语法、已有的默认值或继承及限制、源码引用、核实状态和详情链接。深度内容存在时关联，不要求每条指令都已有完整调用链。仅记录必需字段与行为，不增加通用查询 DSL、动态配置分析接口或模型服务。

检查：按契约读取样例，核对版本、候选和引用；缺失详情、版本不一致或格式不支持时明确失败，不返回拼接的成功结果。JSON 与网页均从共用知识生成。

### 4.3 Codex 本地 MCP 入口

实现最小只读查询工具：接受指令名称或单条配置，以及已有的 context、模块信息；本地解析后匹配索引，通过 HTTP 读取知识详情，返回结构化 JSON、Markdown 和用户可打开的详情及源码链接。工具不接受整份配置分析，不自动读取外部文件，不把原始配置或参数值发送给知识站。

由 Codex 管理 stdio MCP 进程，不开放 HTTP 监听，不独立作为守护服务部署。工具地址等环境配置从配置文件、环境变量或参数传入，不硬编码站点地址。解析与匹配尽量复用 4.1 的能力，JSON 和 Markdown 从同一结果产生，不靠模型重新生成知识。

最低 Agent 验证样例：指令名称、带参数的单条配置、同名且 context 不足、未知指令、单项解析错误、多条配置越界、知识读取失败，以及已有废弃或未核实标记的内容。语法和参数说明不能转化为参数正确或配置安全的判断。

检查：先做离线工具与契约检查，再在首个目标 Codex 中实际接入。用查询请求确认真实工具调用成功，核对 JSON、Markdown 与网站内容一致、核实状态未丢失、引用可访问；对知识站请求检查原始配置及参数值未上传，确认无本地 HTTP 监听。未能接入时记录未完成，不以 Agent 自行回答替代工具验收。

M2 不引入向量数据库、RAG 或内嵌 HTML。接入说明已提供；Codex 配置修改和宿主实测仍待现场条件。

## 五、M3：全范围基础知识

以 M1 的范围矩阵和 M2 验证后的内容结构为准，逐模块完善目录与基础内容。

提取脚本只负责发现注册信息，不能自动证明功能、默认值、继承或运行时行为。功能说明对照实现和文档，配置入口需有可定位源码。未确认的补充内容明示，但缺失功能或入口的指令不得计为完成。

构建时收集源码片段和出处，保留组件、版本、revision、路径和行号。标明来源是上游源码、补丁还是可追溯的补丁后源码，避免版本或行号含义混淆。

检查：逐指令核对必需内容、引用是否可解析、片段与引用是否一致、关联是否失效，检查 JSON 契约和两种展示的数据一致性，生成覆盖缺口清单。全量基础覆盖完成后才满足该阶段验收。
